# ANUM MINE Virtual Headquarters: AI Master Plan
**Version:** 1.0 | **Date:** 2026-10-21 | **State:** Approved design specification and implementation prompts; NOT implemented.
**Target:** Full immersive office on web only; Flutter remains command, agent conversation, tasks, approvals, notifications, summaries and meeting participation by text/voice, without 3D rendering.

Read `README.md`, `CLAUDE.md`, `docs/org-chart.md`, `docs/agents.md`, `docs/agent-runtime.md`, `docs/team-work.md`, `docs/meetings.md`, `docs/events.md`, `docs/realtime.md`, `docs/multi-tenancy.md`, `docs/approvals-and-risk.md`, and `docs/ANUM_OS_Business_and_Product_Master_Roadmap.md` before editing code. No fabricated agent activity or simulated transcripts presented as real. The office is an interface onto verified backend state.

## 1. Verified repository baseline
- `apps/web`: React 19, TypeScript, Vite. Existing `OrgChartView.tsx`, `AgentsView.tsx`, `TeamView.tsx`, `MeetingsView.tsx`, related tests and Playwright e2e.
- `services/api`: FastAPI, agent orchestration, agent profiles, team work, events and SSE, database repositories and migrations.
- `apps/mobile`: shipping Flutter mobile; `apps/android` Kotlin is frozen. Flutter already supports commands, tasks and approvals.
- `packages/contracts`: shared TypeScript contracts.
- Org chart derives members/assistants/agents/tasks/approvals/integrations from real APIs, refreshes on interval; do not break `#agents/team` and profile deep links.
- Meeting feature presently processes imported call recordings/transcripts and Zoom/Teams exports. **It does not run live multi-agent meetings**; implement as a separate clearly named meeting-room capability, reusing analysis and transcript utilities.
- `GET /api/v1/events/stream` supports workspace-scoped resumable SSE. Oracle memory-mode polls persisted events. Avoid one SSE per avatar and do not hold DB sessions open through streams.
- Existing organization/workspace separation, OIDC, authorization, RLS, tool governance and approval rules must remain authoritative.
- Source/documentation is not evidence that provider credentials, CI or production integrations are operational.
- The existing `#office-preview` route is an illustrative CSS perspective tour, not the F04 WebGL renderer or a live office projection. It has a selectable room directory (the initial view on narrow screens) so rooms remain navigable without the perspective scene. Room names and example roles remain preview data; they do not assert agent presence or workspace authorization.

## 2. User experience and scope
The default ANUM MINE web screen is a top-down/isometric **virtual headquarters** with polished architecture, realistic furniture, subtle occupants, daylight/night settings, meeting rooms, workstations, reception, owner office, and department floors. Users can pan, zoom, search an agent, select a room, follow a task, switch workspace, inspect live discussions, review prior meetings and move into task/agent panels. The office must work for 21 existing agents and scale to hundreds via floor filtering, clustering and virtualization. It must remain usable in 2D/list mode, on slow devices, keyboard-only and with reduced motion.

Visual realism is subordinate to data truth:
- Avatar `working` only when assigned active task/run and corresponding server event; `meeting` only while actually participating in an active meeting; `waiting_approval`, `blocked`, `queued`, `idle`, `paused`, `offline/unknown` distinguished.
- Idle is not inferred from a silent UI or 30-second refresh; differentiate active-run, agent enabled, connectivity and missing data.
- Animate transitions only on actual server state; no fake moving employees to suggest ongoing work.
- Meeting conversation is actual saved participant messages; no autogenerated display conversations without clearly marked demo mode.
- Avatar movement is decorative and never required to execute work.

## 3. Workspace model: 360-degree life and business
Owner-level headquarters may navigate separate **Personal & Family**, **Employment & Career**, **ANUM OS**, **Tyre Pulse**, **ANUM360 Store**, **Finance & Wealth**, **Business Operations**, **Sales & Growth**, **Technology & Engineering**, **Operations & Assets**, **Customer Experience**, **Legal & Compliance**, **Research & Intelligence**, and **Security & Governance** departments. Model these as departments, memberships, views and separate authorized workspaces as appropriate, NOT automatic cross-tenant access. Personal and employer data cannot be pooled into sales prompts. Cross-workspace summaries require explicit owner grant, minimum necessary data, policy evaluation and audit; never bypass RLS using an 'owner dashboard'. Existing agents should be mapped, not deleted or renamed without migration. Missing skills/integrations must show honest unavailable statuses.

## 4. Technology plan
**Web rendering:** evaluate Three.js + React Three Fiber + Drei for isometric/orthographic camera, picking, instancing, glTF scene assets, and postprocessing only when needed. Keep heavy scene in dynamically imported route; SSR not required for existing Vite shell. Use compressed models, texture atlases, limited real-time lights, LOD and capped device-pixel ratio. Build initial low-poly architectural prototype with beautiful materials, not expensive photorealistic assets; no unlicensed imagery, models or fonts. Do not add Babylon alongside Three.js. Support GPU-loss recovery, WebGL detection, WebGL unavailable fallback, 2D SVG office map, reduced-motion toggle and a normal accessible task list. Assets/office reference photo come later; make layout data-driven.

**Backend:** keep PostgreSQL canonical state, existing service/repository patterns and SSE; add minimal tables and versioned DTOs for office layouts, workstation assignments, presence projections, live agent meeting sessions/messages/participants and user UI preferences as needed after schema review. Reuse task/run ids, actor attribution, approvals, comments, event correlation and outbox. Derive presence server-side; no frontend invented `active`. All meeting writes are idempotent with per-meeting turn sequence, budgets, cancellation, pause/resume, quorum, max turns/time and moderation. First phase use persisted turn-taking agent meetings with SSE; realtime speech as optional later integration, not a dependency.

**Mobile Flutter:** reuse existing navigation/auth/sessions/command/task/approval flows. Add optional `Office Overview` compact list, `Agent Status`, `Meeting Inbox`, `Join by chat/voice`, `Approve/reject`, `Assign task`, `Summaries` and deep links to browser office; no 3D engine or separate agent backend. Implement flutter features only when API semantics are stable.

**Permission and cost:** workspace-bound RLS on every new table/query; per-participant tool allowlists; no invisible transfer between organizations; transcript retention and deletion controls; secret redaction; browser CSP; rate limits, meeting turn/token caps and spending budget; owner confirmation for sends, purchases, merges, payments, deletions, access grants. Voice-only approval must not bypass existing visual gate.

## 5. Feature implementation prompts, sequential
Each prompt below is to be executed independently, with code/tests/docs in its own PR. Before implementation enumerate touched files, migrations, permission decisions, rollback and API compatibility.

### F01: Baseline audit and architecture ADR
**Prompt:** Inspect current `main` for org chart, agent/task/run state, meeting imports, command, SSE, RLS and Flutter. Build a code-to-feature coverage matrix with endpoints and exact source references; run existing checks locally/CI, record failures honestly, propose a minimal ADR for the office projection and live meeting capability. Do not alter production behavior.
**Acceptance:** evidence-backed baseline; no claims of working features without tests; issue register and rollback approach.

### F02: Office data contract and floor-plan editor
**Prompt:** Design shared versioned office DTOs for department, room, desk, avatar, route and persisted layout in `packages/contracts`. Build authorized APIs for loading and editing layout, schema migration/repository and versioning; allow owner to place agents into desks and rooms with collision/occupancy validation. Layout is per workspace. Unknown agents appear in unassigned roster.
**Acceptance:** RLS, migration downgrade, contract validation, e2e layout save/reload, safe concurrent edits.

### F03: True agent presence projection
**Prompt:** Project canonical agent/run/task and meeting states to a read-only presence API with `working/queued/meeting/waiting_approval/blocked/idle/paused/unknown`; include last verified timestamp, provenance, task reference and stale-state flag. Reuse existing events and SSE with Last-Event-ID; provide snapshot+delta reconciliation and controlled reconnect. Never mark agent busy without evidence.
**Acceptance:** tests for no-run idle, queued, approval wait, cancelled, expired, disconnected, out-of-order/duplicate SSE; workspace isolation; no DB locks held during long streams.

### F04: 3D headquarters web renderer
**Prompt:** Build lazy-loaded React Three Fiber office route with top-down orthographic camera, room/desk geometry, realistic professional materials, lighting, character placeholders, pan/zoom/select, keyboard support, high-DPI responsiveness, asset performance budget and viewport culling. Respect motion preferences. Use server-provided layout/status only and never generate random work activity. Preserve legacy org-chart route as alternate view.
**Acceptance:** working WebGL and fallback screenshots, visual e2e, no console errors, acceptable mid-range laptop FPS measured and documented.

### F05: Floor navigation, department and desk details
**Prompt:** Implement headquarters/floor/room/desk hierarchy, breadcrumbs, minimap, search, filters and status legends. Clicking employee opens existing agent profile, tools, connections, tasks, approvals and provenance; clicking workstation shows real task checkpoints, errors and documents with proper permissions. Don't duplicate existing APIs.
**Acceptance:** deep links, keyboard journey, loading/error/permission states, zero fabricated fields.

### F06: Live meeting-room data model
**Prompt:** Introduce distinct `agent_meeting_sessions`, participants, messages, decisions, action items and meeting events without changing imported-meeting semantics. API can schedule/create/start/pause/cancel/finish/join/leave meeting; cross-workspace participants denied by default. Capture speaker, timestamps, evidence links, turn sequence, budget and transcript policy. RLS and retention apply.
**Acceptance:** migration/rollback, permissions, malformed input, idempotent create, concurrent join tests, transcript export/delete tests.

### F07: Governed multi-agent meeting runner
**Prompt:** Build a backend coordinator that schedules bounded sequential turns from selected workspace agents, supplies least-privilege context, requests structured contribution, persists each message before emitting events, and maintains max turns, time, cost and cancellation. Agents cannot directly bypass the runtime's tool/risk/approval gates. Summarize disagreements and uncertainty, generate draft decisions/action items with linked sources. No artificial 'agent talking' activity.
**Acceptance:** deterministic mocked-model tests, no runaway loops, crash/resume, duplicate event handling, owner interrupt, task handoff, budget exhaustion and no-permission cases.

### F08: Interactive web conference rooms
**Prompt:** Link active meetings to visual room occupancy and participants. Provide live transcript, agenda, speakers, raised hands, join/leave, ask/follow-up, pause/end, meeting notes, file links, decisions and action items through existing UI design system. Visual animated speech only while a real participant turn streams. Preserve imported meeting view.
**Acceptance:** real events drive UI; reconnection replay; escaped Markdown; missing/denied transcript states; playwright meeting journey.

### F09: Persistent work history and replay
**Prompt:** Add owner-authorized timeline across tasks, runs, meeting messages and approvals with correlation IDs, filters and deep links; reconstruct office state at a historical timestamp from server-verified records. Mark incomplete history clearly. No fabricated past states. Retention and sensitive-data redaction.
**Acceptance:** replay matches fixtures; tenant leakage tests; large history pagination; export provenance.

### F10: Executive office and cross-workspace switcher
**Prompt:** Provide owner command desk with authenticated list of accessible workspaces, task counts, blocked work, approvals, costs and meetings. Explicitly switch workspace before opening confidential content. Delegation uses the existing governed command/task APIs and approval workflow. Never use a universal query that circumvents tenant isolation.
**Acceptance:** authorization tests across personal/employer/business, no cross-tenant response contamination, accessible navigation and empty states.

### F11: Realistic office behaviors and visual polish
**Prompt:** Add deterministic animation state machine: idle-at-desk, seated-working, navigating-to-meeting, in-meeting, awaiting-approval, failed/blocked, unavailable. Movement follows actual membership/meeting events; animations are visual-only and always interruptible. Add reception, owner room, break area and subtle soundscape behind explicit sound preference. Avoid uncanny photorealism and performance-heavy crowds.
**Acceptance:** no false status, event-to-animation mapping tests, reduced motion, GPU recovery, memory budget and quality screenshots.

### F12: Mobile Flutter control surface
**Prompt:** Extend existing `apps/mobile` with agent status/search, start or assign task, meeting list and chat participation, transcript review, decisions, approvals and notifications. Reuse `api_client.dart`, OIDC and existing widgets. Deep-link to web office for full 3D. Do not port renderer or recreate meetings backend.
**Acceptance:** flutter analyze/test, phone and tablet sizes, offline/connection error states, strict task/approval parity with web.

### F13: Optional live voice room
**Prompt:** After text meetings are reliable, evaluate a consent-based WebRTC audio room for humans with server-controlled ASR/TTS for agents, explicit costs and microphone access. Store transcripts only according to policy. Allow mute, interrupt and opt out; fallback to text; no automatic external Zoom/Teams joining.
**Acceptance:** documented consent, end-to-end spoken interruption tests, no recording without permission, audio failure recovery.

### F14: Operational readiness, load and deployment
**Prompt:** Perform baseline vs new load tests on Oracle deployment (SSE clients, 21 then 200 agents, meeting turn throughput, database pool), accessibility audits, WebGL fallbacks, security penetration review, analytics, backup/restore, failure injection and feature-flagged staging rollout. Verify CI; do not merge broken checks or deploy by force.
**Acceptance:** approved performance budgets and measured results; staging signoff; rollback rehearsed; production gated on all required checks.

## 6. Delivery gates and recommended order
- **P0:** F01 baseline, close existing critical CI/security failures before office release.
- **P1:** F02 + F03 + F04 + F05: truthful office MVP (no meeting simulation).
- **P2:** F06 + F07 + F08: genuine multi-agent live text meetings.
- **P3:** F09 + F10 + F12: operational command, replay and mobile supervisory parity.
- **P4:** F11 + F13 + F14: refined immersion, optional voice and hardening.
Every PR includes backend/API/contract compatibility matrix, migration and rollback, tests for RLS and approval boundaries, visual QA, cost/performance observations, and updated documentation. Track `not started / in progress / tested / deployed` accurately; a plan is not implementation.
